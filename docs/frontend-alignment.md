# 前端与产品设计对齐清单

这份清单把[产品设计](product-design.md)中的原则落实为可验收的页面职责。它不另立产品方向，只用于防止 Flutter 界面把目标态、实验能力和当前生产承诺混在一起。

## 全局不变量

1. 首个生产版本只公开物品的“出 `offer` / 收 `wanted`”；找人、帮忙、活动仍是后续路线，不出现在当前发布入口或公开 Feed。
2. 小昌是平台工具，不是联系人。它可以从首页或工具按钮进入，但不能作为一条人际 Thread 固定在消息收件箱。
3. 留言、连接和主动确认只展示技术事实与用户主动行为；界面不得出现在线、正在输入、最后上线或自动已读。
4. 用户角色化分身与校园认证、小昌身份分层展示。角色只能从系统目录选择，不能上传或导入角色/皮肤。
5. 导航高亮必须反映页面职责：首页与小昌属于发现/辅助路径，消息只承载人与人的 Thread/Space，发布表单始终属于发布入口。
6. Agent 不可用时，浏览、出/收发布、消息与个人设置仍有可发现的手工路径。

## 页面职责与验收

| 页面 | 当前职责 | 必须出现 | 不应出现 | 状态 |
| --- | --- | --- | --- | --- |
| 登录 | 建立账号会话 | 登录/注册、校园身份提示、品牌 | 未登录仍进入主壳、失效会话停在错误页 | 已有页面；失效会话回归仍需专项验收 |
| 首页 | 同时发现“出”和“收”，可选进入小昌 | 出/收筛选、条目级解释、明确发布入口 | 只有 Agent 大卡、把 wanted 藏在搜索失败后 | P0 已校正空态和出/收入口 |
| 发布 | 用一句话或完整表单发布物品出/收 | 出/收二分、完整商品表单入口、失败保留输入 | 找人/帮忙/活动等未承诺类型 | P0 已校正 |
| 消息 | 联系人 Thread、独立留言/连接边界和群组实验入口 | 联系人聚合、新留言本地标记、连接/留言筛选 | 小昌作为联系人、已读/typing/online | P0 已把小昌移出 Thread；关系空间视觉仍待深化 |
| 关系空间 | 恢复双方确定性历史并发起留言或连接 | 双方角色、Conversation 卡组、时间与 Pin、共享内容 | 无限混排消息流、AI 推断关系强度 | P1 |
| 个人页 | 管理身份、角色化呈现、校园与隐私 | 当前公开角色预览、校园认证、发现/连接设置 | 用大量无层级菜单替代身份入口 | P1 |
| 商品详情 | 判断是否适合并推进联系/线下成交意向 | 权威字段、解释、留言/连接、状态与限制 | “付款成功”“平台担保”等错误承诺 | P1 |
| 小昌 | 搜索、解释、草拟和受控执行 | Agent 明确标识、草稿/确认卡、失败降级 | 伪装成人、自动发送、成为消息收件箱联系人 | P0 已分离入口；状态视觉 P2 |

## 实施顺序

### P0：结构与承诺

- 统一品牌为“续樟 / Goods4ncu”。
- 首页空态也显示出/收同级筛选与两个发布动作。
- 发布页只公开物品出/收，并保留完整表单入口。
- 小昌退出联系人列表，以独立工具动作进入。
- 修正 `/create/listing` 与 `/chat` 的导航归属。
- 公开 Feed 不再混入历史非物品意图。

### P1：关系与身份

- 把 Thread 详情收敛为 Relationship Space 投影，而不是左右拼接的传统聊天窗口。
- 完成角色 24/48/160 三档在首页、Thread、资料和空间中的一致使用。
- 重排个人页：公开身份与边界优先，管理菜单降级为次级区域。
- 重做商品卡和详情的信息优先级，让出/收方向、价格语义、解释来源和状态一眼可区分。

### P2：视觉与弱网

- 建立统一页面栅格、密度、空态、错误态、加载态和桌面/移动断点。
- 验证 200% 字号、键盘导航、reduced-motion、深色模式和媒体失败回退。
- 用真实双账号走通留言、连接、主动确认、结束连接、跨校园隔离与 Agent 降级。

## 完成定义

每轮界面改造必须同时通过：对应 Widget 测试、`flutter analyze`、完整 `flutter test`，以及本地 Web 上的真实账号逐页验收。截图好看不算完成；页面职责、状态语义和失败路径必须与产品设计一致。
