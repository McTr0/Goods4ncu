# 前端与产品设计对齐清单

这份清单把[产品设计](product-design.md)中的原则落实为可验收的页面职责。它不另立产品方向，只用于防止 Flutter 界面把目标态、实验能力和当前生产承诺混在一起。

## 全局不变量

1. 首个生产版本只公开物品的“出 `offer` / 收 `wanted`”；找人、帮忙、活动仍是后续路线，不出现在当前发布入口或公开 Feed。
2. 小昌是每位用户私有的核心 Avatar 与工具入口，不是联系人。它固定在主导航中央，不能作为一条人际 Thread 或消息页右上角附加按钮出现。
3. 留言、连接和主动确认只展示技术事实与用户主动行为；界面不得出现在线、正在输入、最后上线或自动已读。
4. 用户角色化分身与校园认证、小昌身份分层展示。角色只能从系统目录选择，不能上传或导入角色/皮肤。
5. 导航高亮必须反映页面职责：首页、消息、小昌、发布、我的各自独立；手机端小昌位于底部中央并突出显示，消息只承载人与人的 Thread/Space。
6. Agent 不可用时，浏览、出/收发布、消息与个人设置仍有可发现的手工路径。
7. SocialPersona Avatar 完全取代传统用户头像产品功能；未配置或不可用时使用默认系统 Avatar，不渲染照片、`avatar_url` 或用户上传头像。当前 Flutter 使用类型化本地状态机与可替换 renderer，默认系统角色采用 Sprite Atlas，已配置角色及失败路径采用代码绘制；24px 静态、较大尺寸允许低频本地 idle。
8. 常驻界面文案使用明确的名词、状态和操作，不用“说出来”“我能帮”“接下来可以”等自言自语式引导；权限说明只在创建、设置或受限操作时按需呈现，不重复堆在列表卡片上。
9. 除登录页外，应用页面始终位于主导航壳层内：移动端保留底部栏，桌面端保留侧边栏；聊天、空间、商品详情、设置和管理页不得脱离主导航。

## 页面职责与验收

| 页面 | 当前职责 | 必须出现 | 不应出现 | 状态 |
| --- | --- | --- | --- | --- |
| 登录 | 建立账号会话 | 登录/注册、校园身份提示、品牌 | 未登录仍进入主壳、失效会话停在错误页 | 已有页面；失效会话回归仍需专项验收 |
| 首页 | 同时发现“出”和“收”，可选进入小昌 | 出/收筛选、条目级解释、搜索入口；发布统一走底部“发布” | 只有 Agent 大卡、把 wanted 藏在搜索失败后、重复展示发布快捷按钮 | P0 已校正空态和出/收入口 |
| 发布 | 使用标准商品表单发布物品出/收 | 结构化字段、突出图片识别、失败保留输入 | 意图快捷标签、校园 Feed、“我的发布”等重复区块 | P0 已改为标准表单 |
| 消息 | 联系人 Thread、独立留言/连接边界和群组实验入口 | 联系人聚合、新留言本地标记、连接/留言筛选 | 小昌作为联系人、已读/typing/online | P0 已把小昌移出 Thread；关系空间视觉仍待深化 |
| 关系空间 | 承载单次 realtime Conversation | 占满主画布；对方 Avatar 左上、我方右下；消息、状态和共享信息在空间内；底部仅输入与操作 | 空间下方再堆消息流、“说好的事”卡片、跨会话历史或 AI 推断关系强度 | P1 已完成主画布重排 |
| 个人页 | 管理身份、角色化呈现、校园与隐私 | 当前公开角色 Avatar/默认系统 Avatar、校园认证、发现/连接设置 | 用照片头像、`avatar_url` 或角色外观替代校园认证 | P1 |
| 商品详情 | 判断是否适合并推进联系/线下成交意向 | 权威字段、解释、留言/连接、状态与限制 | “付款成功”“平台担保”等错误承诺 | P1 |
| 小昌 | 搜索、解释、草拟和受控执行 | 个人核心 Avatar、中央导航、草稿/确认卡、失败降级 | 伪装成对方、自动发送、成为消息收件箱联系人 | P0 已成为独立中央入口；状态视觉 P2 |

消息输入区使用统一的 `UnifiedMessageComposer` 骨架，统一输入、附件、发送中状态、回复预览和扩展工具的交互。宿主页面只注入与当前上下文相关的能力：群组可展开接龙、群收集和投票；实时连接可展开引用、语音通话和视频通话；小昌可展开找商品、发布商品和价格参考。页面顶部不提供含义重复的关闭或刷新图标；群组/频道通过下拉手势刷新，异步结果必须采用请求代次保护，旧响应不得覆盖新状态。

## 实施顺序

### P0：结构与承诺

- 统一品牌为“续樟 / Goods4ncu”。
- 首页空态也显示出/收同级筛选与两个发布动作。
- 发布页默认展示完整商品表单，图片识别位于首屏突出区域；不混入首页 Feed 或个人发布记录。
- 小昌退出联系人列表与消息页工具栏，以主导航中央的个人核心 Avatar 进入。
- 所有登录后路由统一进入主导航壳层；`/create` 作为唯一标准发布入口，`/create/listing` 仅保留兼容重定向。
- 公开 Feed 不再混入历史非物品意图。

### P1：关系与身份

- 把 Thread 详情收敛为 Relationship Space 投影，而不是左右拼接的传统聊天窗口。
- 完成角色 24/48/160 三档在首页、Thread、资料和空间中的一致使用。
- 让 SocialPersona Avatar 成为唯一用户头像呈现；采用纯 Flutter 状态机 + Sprite Atlas，按 24px 静态、48px 低频动效、160px 完整交互实施，失败/reduced-motion 回退同角色静态 poster；只有关系空间需要多角色移动、碰撞或粒子时才局部引入 Flame。
- 重排个人页：公开身份与边界优先，管理菜单降级为次级区域。
- 重做商品卡和详情的信息优先级，让出/收方向、价格语义、解释来源和状态一眼可区分。

### P2：视觉与弱网

- 建立统一页面栅格、密度、空态、错误态、加载态和桌面/移动断点。
- 验证 200% 字号、键盘导航、reduced-motion、深色模式和媒体失败回退。
- 用真实双账号走通留言、连接、主动确认、结束连接、跨校园隔离与 Agent 降级。

## 完成定义

每轮界面改造必须同时通过：对应 Widget 测试、`flutter analyze`、完整 `flutter test`，以及本地 Web 上的真实账号逐页验收。截图好看不算完成；页面职责、状态语义和失败路径必须与产品设计一致。
