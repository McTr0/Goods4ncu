## 一、诊断：问题不在"有社交表"，在于社交的**形态是抄的**

社区需要聊天、需要空间、需要语音——这些都该有。真正的问题是它们的**组织方式**照搬了微信/贴吧：

| 抄来的形态 | 在校园社区里的实际后果 |
| --- | --- |
| **预设频道/板块**（`chat_spaces`） | 鬼城。南昌大学三万学生，但"考研数学互助""羽毛球搭子""手工陶艺"每个细分只有一二十个活跃的人，摊在一堆没人进的房间里，进去看到上条消息是三周前，就再也不来了 |
| **消息流是唯一真相** | 约个球局聊 30 条，"周几、几点、几个人、哪个场"要往回翻 |
| **要先知道去哪个房间** | 新生根本不知道该去哪，也不知道有谁 |
| **活跃度指标**（发帖量 / DAU） | 追它会推着产品变成信息流，而不是让人真正认识人 |

交易侧同样是抄的（表单、分类、收藏夹、讲价拉锯），但它只是社区的一个子集，一并处理。

**AI 现在的位置**：小帮是挂在旁边的一个"也能帮你发商品"的助手。判据不变：

> **把 AI 拿掉，产品照样能用 → 那它就不是 native 的。**

## 二、统一命题：一个意图引擎，三类意图

这是 v2 的核心洞察，也是"社区带交易"这个定位真正成立的地方。

**校园社区里发生的一切，本质都是意图与意图的配对：**

| 类型 | 例子 | 传统做法 |
| --- | --- | --- |
| **物** | "宿舍这个小冰箱想出掉" / "想收个二手显示器" | 发商品 / 搜索 |
| **人** | "找个羽毛球搭子" / "想找同专业考研的一起自习" | 进群碰运气 |
| **事** | "有人会修自行车吗" / "拼个奶茶" / "周末想爬梅岭有人去吗" | 发帖等回复 |

传统产品用**三套不同的机制**处理它们（商品系统 / 群聊 / 论坛发帖）。

**AI-native 的做法是同一套**：都是意图 → 都进撮合池 → 都产出共识空间。

```
        意图（物 / 人 / 事）
              ↓
          撮合引擎
              ↓
         共识空间
    ┌─────────┴─────────┐
  成交（物）        约定（人 / 事）
  什么/多少钱        谁/何时/何地
  /何时/何地          /带什么
```

交易不是被特殊对待的模块，它是**共识空间的一个 kind**。这就是"社区恰好带交易"在架构上的样子。

### 关于"人际交互方便"

不是少和人打交道——校园社区的价值恰恰是**让人认识人**。要消除的是摩擦，不是接触：

| AI 接管（摩擦） | 留给人（实质） |
| --- | --- |
| "在吗""还在吗"的无效往返 | 见面时的判断与信任 |
| 讲价拉锯、开口的尴尬 | 要不要跟这个人成交 |
| 反复约时间、翻聊天记录找地点 | 当面的相处 |
| 不知道该去哪个群、该找谁 | 愿不愿意和这个人成为朋友 |
| 发的东西没人回的冷场 | 真正想聊的内容 |

一句话原则：

> **AI 处理事务，人处理关系。**

## 三、七条设计原则

1. **意图是一等公民。** 物、人、事共用一套意图模型，listing 和帖子都只是投影。
2. **状态优先于消息流。** 一次约定的真相是"谁 / 何时 / 何地 / 说好了什么"，不是 30 条消息。消息是对状态的注释。
3. **不预设容器。** 频道不该由运营预先划好等人来，应该由真实需求临时长出来，目的达成就自然归档。
4. **能撤销优于先确认。** 低风险动作让 AI 直接做、留撤销窗口；只有钱和身份才事前确认。
5. **主动性必须有预算。** 社区产品死于推送骚扰的概率比死于不智能高得多。
6. **不确定就说不确定。** 槽位可以空、可以是范围、可以是"无所谓"。逼用户填完整是表单思维。
7. **AI 挂了社区要还能用。** 快路径（关键词 / 向量）永远保留，LLM 只在歧义时介入。

## 四、阶段计划

### Phase 0：撤销基础设施 + 打扰预算（地基，先做）

两者都小、都独立、都立刻改善体验，且是后续所有阶段的前置。

**撤销基础设施**——见附录 A 决策三。每个 L2 动作（发布、改价、下架、加入、退出）必须可逆：记录反向操作、幂等、有时间窗。这不是可选项，是 Phase A / B 的硬依赖。

**打扰预算**——每用户每日打扰上限（初始 3 次）在**架构层**强制，不是 UI 层。每次主动打扰携带 `reason` 和 `expected_value`，低于阈值不发。接受率作为一等指标，被忽略的类型自动降权。

**退出门槛**
- L2 动作 100% 可逆，撤销幂等，有并发测试
- 日打扰上限有架构层测试（绕不过去）
- 用户可查看"为什么给我推这条"
- 打扰接受率 ≥40%，否则自动收紧

### Phase A：意图层（物 / 人 / 事）

**为什么不是传统做法**：传统产品要求你先把想法**塞进某个模块的表单**——卖东西填商品表单，找搭子发帖到某个板块。这道门槛把大量"其实有需求但懒得折腾"的人挡在外面。毕业季一个宿舍二十件东西没人填二十次表单；想找人打球的也懒得为这个专门发帖。

**做什么**

- 新增 `intents` 表：`kind`(goods_offer / goods_seek / companion / help / activity)、`raw_input`、`slots`(JSONB)、`confidence`、`valid_until`、`status`、`visibility`
- 一次输入可产出**多个意图**：一张宿舍照片 → 6 件物品；一句"毕业了东西都不要了，顺便找人接手我的自习座位" → 物品意图 + 转让意图
- 槽位允许**缺失和模糊**：`price: {kind:"whatever", hint:"能卖就行"}`、`time: {kind:"flexible", hint:"这周都行"}` 都是合法状态
- `inventory` 降级为 goods 类意图的**展示投影**（兼容现有前端），由意图变更驱动同步

**AI 的具体职责**：多模态拆解（图 → 物品清单）、意图类型判别、槽位抽取与置信度、模糊表达归一化、过期判断。

**退出门槛**
- 一张宿舍照片产出 ≥5 件物品，平均编辑 ≤1 次/件
- "能卖多少卖多少""这周都行"这类无确定值意图可走完全流程
- 三类意图（物 / 人 / 事）共用同一套 API，无特化分支
- 意图 → listing 投影双向一致，有回归测试
- LLM 不可用时纯文本仍可创建意图（降级为单件 + 关键词）

**风险**：拆解错误产生垃圾意图。缓解——结果一律先进"待确认"，不确认不进撮合池。

### Phase B：共识空间（交易只是一种 kind）

**为什么不是传统做法**：不管是买卖还是约球，两个人聊完，"到底几点、在哪、多少钱、几个人"都散落在消息流里。IM 的数据模型是**消息流**，而一次约定的真相是**一份逐渐成形的共识**。用消息流承载共识，等于让用户在脑子里跑状态机。

**做什么**

- 新增 `agreements` 表：一次约定的**活状态**，按 kind 有不同槽位
  - `deal`（交易）：`item` / `price` / `meet_time` / `meet_place` / `conditions`
  - `meetup`（约人约事）：`what` / `when` / `where` / `who` / `bring`
  - 每一项带 `agreed_by`——谁确认了，谁还没
- 界面顶部常驻**共识卡片**，参与者看到的完全一致，改动即时同步
- 消息**降级为注释**：AI 从对话抽取状态变更并**提议**——"他说周三下午 → 把时间改成周三 15:00？"一键采纳
- 变更全部留痕（谁改的、依据哪句话），可回溯
- 现有 `chat_conversations` 保留，作为共识空间的会话载体

**明确保留**（v1 曾错误地列为下线）：`chat_message_reactions`（社区里的轻量回应，降低表态门槛）、`chat_calls` 与信令、`chat_blocks` / `chat_message_reports`。typing、online、last seen 和自动已读不再作为长期产品方向；realtime 的明确连接状态足以表达双方正在参与，留言只公开送达所需的技术事实和用户主动 acknowledgement。

**AI 的具体职责**：从自然对话抽取槽位、检测共识分歧（"你说三点他说四点"）、生成待办提醒（"明天 15:00 体育馆 3 号场，记得带球拍"）。

**退出门槛**
- 一次典型约定 / 成交，用户**不需要向上滚动**就能看到全部关键信息
- 状态抽取在标注集上准确率 ≥90%，且**错误提议不会自动生效**（必须一方明确采纳）
- deal 与 meetup 共用同一套共识机制，无特化分支
- 从"首次接触"到"约定成型"的消息数中位数下降 ≥40%

**风险**：抽取错误导致双方对"说好了什么"理解不一致。缓解——AI 只提议不落地；分歧检测优先级高于便利性。

### Phase C：临时聚合取代常驻频道

**这是社区侧最重要的一步，直接治鬼城。**

**为什么不是传统做法**：贴吧 / Discord 式的预设板块假设"先有房间，再有人来"。在单个校园的规模下这必然失败——细分兴趣的活跃人数撑不起常驻房间，进去看到三周前的消息就再也不来了。运营再怎么建群也是在制造更多空房间。

**做什么**

- **不预设频道**。AI 根据真实意图密度**临时生成聚合**：当"周末想爬梅岭"的意图在 48 小时内出现 5 条，自动成一个空间，把这 5 个人拉到一起
- 每个空间有**明确目的和预期寿命**：目的达成（球打完了、山爬完了、拼单成了）即自动归档，不留尸体
- 长期稳定的兴趣（持续有意图流入）可以**沉淀**为长驻空间——但那是**长出来的**，不是运营划出来的
- 复用现有 `chat_spaces` 表，新增生命周期字段：`origin`(ai_formed / promoted / manual)、`purpose`、`expected_lifespan`、`archived_at`、`formation_reason`

**为什么这更方便**：新生不用知道"该去哪个群"。他只要说"想找人一起打球"，人就出现了。

**AI 的具体职责**：意图聚类与密度判断、成团时机（人太少没意思，太多没归属感）、目的达成判定、归档时机、沉淀为长驻的判断。

**退出门槛**
- 用户**从不需要浏览频道列表**也能参与到社区活动
- 归档率健康：AI 生成的空间中 ≥70% 在目的达成后正确归档
- 无鬼城：活跃空间中"最后一条消息超过 14 天"的占比 <10%
- 成团人数有上下界，且下界不达标时明确告知而非硬凑

**风险**：**小圈子固化与信息茧房**。AI 按相似度聚合，容易把人锁在同质圈子里，这在校园里是真实的社会危害（本就存在的院系 / 地域隔阂被算法放大）。缓解——聚合必须保留随机性配额；同一用户重复聚合到高度重合人群时主动引入新人；这一条要作为**硬指标**监控，不是"注意一下"。

### Phase D：撮合取代搜索与发帖

**当前工程状态（部分完成）**：首页商品 feed、相似商品、listing wanted matches 和统一意图 feed/matches 已有同校园硬过滤、可理解解释/稳定来源、排序版本，以及“隐藏 / 少推荐这类 / 与我无关”、非个性化排序和重置旧信号；其中新撮合入口使用客户端可本地化的稳定解释 code，兼容中的首页商品 feed 仍可返回服务端人话原因。解释只来自生命周期和用户已声明/实际执行的约束，不调用 LLM 编造原因。listing matches 在硬分类内用服务端派生的同品牌事实处理泛化反馈；跨表达软排序、匹配置信度校准与真实有效匹配率仍待完成。

**做什么**

- 三类意图**对等**进入撮合池。goods_seek 不再是二等公民，companion / help / activity 与 goods 同权
- 每个匹配带**人话理由**和置信度："他刚发的显示器，你上周说想要 24 寸以内、300 以内 —— 尺寸和价都对得上"
- 硬约束前置（校园、状态、方向、可见性），软排序在后
- 搜索框**降级为兜底**入口，不再是主路径

**AI 的具体职责**：跨表达匹配（"显示器"↔"屏幕"↔"外接屏"；"搭子"↔"一起"↔"有人吗"）、约束满足判断、理由生成、通知时机判断。

**退出门槛**
- 模糊需求（无品牌无型号 / 无具体时间）能拿到有效匹配
- 硬约束违反率为 0
- [工程已实现，效果待验证] 首页商品、相似商品、listing wanted matches 与 intent feed/matches 有可理解理由和“不感兴趣 / 别再推这类”反馈入口
- 无 embedding 时关键词兜底可用

### Phase E：价格发现取代讲价 ✅ 已确认要做

**为什么不是传统做法**：闲鱼式讲价是**公开拉锯**。在校园熟人半熟人语境里这非常伤面子——开低了怕显得没诚意，拒绝了怕伤和气，很多交易死在"不好意思开口"。社区里更严重：今天砍价砍崩了，明天还要在食堂碰见。

**做什么（opt-in，双方都同意才启用）**

- 双方**私下**告诉小帮自己的心理价：买家最高愿付 B，卖家最低愿收 S
- 小帮**只回答能不能成、成在什么价**，绝不泄露对方数字
- 规则公开透明：若 B ≥ S，成交价取区间中点（或双方事先同意的其他规则）；若 B < S，只回"这次没谈拢"，**不说差多少**

```
买家：我最多 280          卖家：我最少 250
小帮 → 双方：可以成交，265
（双方都不知道对方报了多少）
```

把讲价从**人际对抗**变成**机制计算**。没有拒绝、没有还价、没有伤面子——这对一个大家会反复见面的社区尤其重要。

**风险与边界（必须正视）**
- **策略性谎报**：买家可能报得低于真实意愿。缓解——校园是重复博弈 + 实名；规则明示"报价即承诺，成交后反悔计入信用"；且 opt-in，不想用的人走原有还价流程
- **不能是黑箱**：定价规则必须写在界面上，用户能复述"为什么是这个价"
- **不适用于所有品类**：高价值物品建议仍走面议
- **底价是最敏感数据**：绝不能出现在任何接口响应、日志或模型上下文中

**退出门槛**
- 规则界面可读，用户能复述定价逻辑
- 双方底价在接口 / 日志 / 模型上下文中**零泄露**，有专门的泄露测试（比照现有 confirmation token 的防泄露测试）
- opt-in 率与成交率有对照数据；若无提升则撤回

### Phase F：社区健康与信任

**为什么不是传统做法**：五星评价是电商抄袭。在一个大家会反复见面的校园社区里，它既失真（都给五星）又伤和气（不敢给差评，给了要面对面）。

**做什么**

- 交接 / 聚会完成后的**轻量事实确认**：东西对不对、人是否到场——只记可验证事实，不做主观打分
- 信誉由**完成次数**和**守约率**构成，不是星级："完成 12 次约定，守时 11 次"
- 爽约影响撮合权重，但**不公开羞辱**
- 新用户冷启动保护：无历史不等于被埋没

**退出门槛**
- 信誉信号可解释
- 无差评机制导致的报复行为
- 新用户在无历史时仍能获得撮合机会

## 五、怎么衡量成功

传统社区看 DAU、发帖量、停留时长。**追它们会把产品推回信息流克隆。**

社区的真正产出是**人认识了人**，交易的真正产出是**东西真的换了手**：

| 指标 | 说明 | 为什么 |
| --- | --- | --- |
| **新增真实关系数** | 因平台第一次产生互动、且后续还有互动的人对 | 社区的真正产出 |
| **意图被回应率 / 首次回应时长** | 说了没人理 = 社区失败 | 冷场是社区第一死因 |
| **约定完成率** | 意图 → 真的见面完成的比例 | 覆盖交易与非交易 |
| **达成共识所需消息数** | 中位数 | 直接衡量"人际交互是否变方便" |
| **新人第 7 日留存** | 归属感 | 不是 DAU，是"新人有没有被接住" |
| **人均日打扰次数 / 接受率** | 越低 / 越高越好 | 防止退化成推送机器 |
| **聚合多样性** | 重复聚合到同一批人的比例 | 防信息茧房（Phase C 硬指标） |
| **无 AI 时可用率** | 降级路径健康度 | 不能把产品押在 LLM 可用性上 |

明确**不看**：消息条数、发帖量、停留时长、DAU。

### 这些指标已经可以查询

不再只是主张。`GET /api/admin/community-health?days=30`（管理员，按校园隔离）返回上表中除"聚合多样性"和"无 AI 时可用率"外的全部读数——前者要等 Phase C 的聚合真正存在，后者属于运维指标。实现见 `src/services/community_health.rs`，定义由 `tests/community_health_integration.rs` 钉住。

几个定义上的判断，写在这里以免日后被悄悄改掉：

- **完成率的分母是"被回应的发帖"，不是"全部发帖"**。除以全部发帖会把"被回应率"折叠进来，让一个"发帖没人理"的社区看起来像"谈不成生意"——两种病，药方完全不同。
- **关系需要第二次互动才算数**。"认识了"很廉价，"又找回来了"才是社区在起作用。人对是无序的（A 找 B 和 B 找 A 是同一段关系）。
- **被忽略的通知不算拒绝**。接受率的分母是"有明确反馈的"，把沉默当拒绝会让系统比证据所支持的更不敢打扰。
- **关系只出总数，不出是谁**。单个校园里谁和谁来往是敏感信息，运营看板没有理由暴露。

首次实测（无真实用户的本地部署）：发帖被回应 **0/2**，其余各项无样本。这是正确的基线——**在有真实学生使用之前，"最好的社区"这个目标不可能被验证，只能被测量准备好。**

## 六、成本与延迟

意图理解、状态抽取、聚类、撮合理由都是 LLM 调用，成本和延迟是主要约束。

- **快路径优先**：结构完整、无歧义的输入走本地规则 / 向量，不调 LLM
- **LLM 只在歧义时介入**，结果缓存（同一意图不重复解析）
- **预算护栏**：每用户每日 LLM 调用上限，超出降级到快路径
- **首 token 延迟目标**：交互式 <1.5s；后台任务不设限但要有进度反馈

现有熔断器与超时边界（连接 10s / 读 60s）继续生效。

## 附录 A：三项已决策事项

**决策一：Phase E（AI 定价撮合）——做。**
最非传统、最可能出彩的一条。风险已在 Phase E 中列明，特别是底价零泄露必须有专项测试。

**决策二：社交层不下线——产品是社区，交易是其中一种互助形式。**
这推翻了 v1 的核心判断。影响：下线清单作废；`chat_spaces` 从删除改为改造；新增 Phase C（临时聚合）作为社区侧核心；指标体系从"成交"扩展到"关系"；意图模型从"物"泛化到"物 / 人 / 事"。

**决策三：ActionPlan 从"事前确认"改为"分级 + 可撤销"。**（由我决定）

用人话说清楚这是什么：

> **现在**：小帮想帮你改个价，先弹窗问"确定要改成 265 吗？"→ 你点确定 → 才真的改。**每次都问，很烦。**
>
> **改成**：小帮直接改好，然后在结果旁边放个「撤销」按钮，5 分钟内点一下就还原。
>
> **例外**：涉及钱和身份的（确认成交、公开收款码），还是先问——但做成结果页上的一次点击，不是让你去另一个"待确认"列表里翻。

为什么这样更好：大部分时候 AI 判断是对的，先问等于白问一次；少数时候错了，撤销一下就行。**用"错了能改"换掉"每次都问"。**

| 风险级 | 现在 | 改为 |
| --- | --- | --- |
| L1 读取（搜索、查看） | 直接执行 | 不变 |
| L2 写入（发布、改价、下架、加入空间） | 弹确认 | **直接执行 + 5 分钟撤销窗口** |
| L3 钱 / 身份 / 公开（成交意向、收款码） | 弹确认 | **保留事前确认**，但内联在结果流里 |

安全底线不变：confirmation token 仍不进模型上下文，L3 仍需二次确认，工具层滥用测试集继续跑。代价是要新建撤销基础设施（Phase 0）。
